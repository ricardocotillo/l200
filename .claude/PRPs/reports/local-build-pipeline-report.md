## Deviations from Plan

1. **`#ffba43` grep assertion fails, but the color survived.** Tailwind's `--minify` flag runs cssnano, which rewrites hex colors to `rgb(255 186 67 ...)` / `rgba(255,186,67,...)` notation rather than keeping the literal `#ffba43` string. The plan's Testing Strategy table asserts `grep -c '#ffba43' css/index.css` ≥ 1; actual count is 0. Verified the token compiled correctly by grepping the RGB triplet instead (`rgb(255 186 67` appears in `.text-tertiary`, `.border-tertiary`, etc.). This is a minifier output-format difference, not a purge failure — the combined assertion (`border-tertiary\|#ffba43\|120px\|opacity-60` ≥ 4) still passes because the other three terms match.
2. **Task 7 / browser validation done structurally, not visually.** No browser automation tool was available in this session. Substituted grep-based structural checks (head order, no inline style/script remaining, WhatsApp arbitrary color intact, mobile-variant classes present in source) for the plan's screenshot-diff and live click-through. **The user should open `index.html` in a browser and run through the Edge Cases Checklist below before merging**, particularly the carousel's selected-thumbnail border/opacity toggle, which is the one regression risk this plan calls out explicitly.
3. **npm `allow-scripts` blocked esbuild's postinstall.** No plan impact — esbuild's Linux x64 binary was already present in `node_modules/@esbuild/linux-x64` and the CLI works (`npx esbuild --version` → `0.28.2`). Left as-is rather than running `npm approve-scripts`, since nothing was broken.
